## 1. 命名

### 主推：**Anchor**

| 项 | 值 |
|---|---|
| 英文名 | **Anchor** |
| 中文副标 | 自制力协议 |
| 英文副标 | A Protocol for Self-Control |
| 域名/仓库 | `anchor`（部署路径 `/anchor/`，需同步设置 Vite `base`） |

**为什么是 Anchor：**

1. **方法论内核**：原文的核心机制是"神圣座位"——一个可触摸、可定位的**实体锚点**；攻略三也直接引用《原子习惯》的"锚点效应"。命名与方法论同构，不用"自律""效率"这类已被玩坏的词。
2. **音形**：6 个字母，两音节，元音开口大，中英文母语者都能一次读对；Android 桌面图标在小尺寸下仍可辨。
3. **视觉**：大写衬线体排成 `ANCHOR` 有"锚链沉船"的重量感，有工程感但不冷漠——正好是原文"我要走 technology 的路，而不是 advice 的路"的气质。
4. **语义张力**：锚是用来**让船停在确定位置**的。对一个总是漂在"今晚刷手机还是学习"里的人，"把自己锚定"是准确的隐喻。同时锚也是**限制**（约束你只能在这一处落座）——一词双关，正好覆盖"限制"与"固定"两层含义。

**备选及否决理由：**

| 备选 | 否决理由 |
|---|---|
| Protocol | 与原文「协议」呼应，但太泛、无具象感，App 图标不可辨 |
| Ledger | 只覆盖判例账本一面，丢失"树"和"链" |
| Keystone | 语义好，但 8 字母且略拗口 |
| Pledge | 承诺感强，但隐含"道德压力"，违背原文反说教调性 |

### 命名纪律
- 产品内**不出现**"自律""坚持""打卡""连续天数""挑战""目标"等词。
- 国策即原文"定式"，链即原文"链式时延协议"，判例即"下必为例"。概念名尽量沿用原文，不另造黑话。

## 2. 字体

### 2.1 三族分工

| 用途 | 字体 | 理由 |
|---|---|---|
| 标题 / 品牌字 | **Instrument Serif**（400） | 现代衬线，克制有权威感，与"工程论文"气质吻合；拉丁字符子集极小（~20KB） |
| 界面 / 正文 | **Inter** | 中性、字面率高、小字号可读性最好，变量字体体积可控 |
| 数字 / 代号 | **JetBrains Mono**（400/500） | 链号 `#1`、时间戳、判例 ID、熟练度——等宽带来"仪表盘/日志"的工程质感 |

> **关键决策：不用中文衬线做标题。** 中文衬线（宋体类）在 Android 上渲染质量差异极大，且和 Instrument Serif 的西文气质难以统一。中文标题统一走黑体加粗，字号/字重/字距做层级区分。气质差异用**留白和色彩**解决，不靠字体冒险。

### 2.2 中文字体栈（Android 优先）

```
system-ui,                         /* Android → Roboto + 设备中文默认字 */
"HarmonyOS Sans SC",               /* 华为 */
"MiSans",                         /* 小米 */
"Noto Sans SC",                    /* 通用回退 */
"PingFang SC",                     /* iOS（本项目非目标，但保留） */
"Microsoft YaHei", sans-serif
```

关键点：Android 的 `system-ui` 会自动落到设备自带中文黑体（HarmonyOS Sans / MiSans / Noto Sans CJK），**在各品牌机器上都是系统级高质量渲染**，且零下载成本。

### 2.3 字体加载策略（不可省略）

> ⚠️ **国内用户访问 Google Fonts 不稳定**，必须自托管。

- 三个西文族全部**自托管 woff2**，放 `public/fonts/`，`font-display: swap`。
- **拉丁子集化**（`unicode-range` 或按字符集裁剪），不加载完整 CJK。
- Inter 用**可变字体单文件**（wght 400–700 一个文件），比 4 个静态字重更省。
- 预估总字体开销 **≤ 90KB**（gzip 后更小），且不阻塞首屏。

### 2.4 字阶（移动端，基准 16px）

| Token | 字号/行高 | 字重 | 字距 | 用途 |
|---|---|---|---|---|
| `display` | 44 / 1.0 | 400 | -0.015em | 品牌字 Anchor |
| `h1` | 24 / 1.30 | 600 | -0.01em | 页面标题 |
| `h2` | 19 / 1.35 | 600 | 0 | 卡片标题 |
| `h3` | 17 / 1.40 | 600 | 0 | 小节标题 |
| `body` | 16 / 1.60 | 400 | 0 | 正文（**下限，不可小于 15**） |
| `body-sm` | 14.5 / 1.55 | 400 | 0 | 次要正文 |
| `caption` | 12.5 / 1.40 | 500 | +0.02em | 标签、时间戳、辅助说明 |
| `mono` | 13 / 1.0 | 500 | 0 | 链号、ID、数值（`font-variant-numeric: tabular-nums`） |

**可访问性硬性要求**
- 正文最小 15px；`caption` 12.5px 只用于非关键辅助信息，且其颜色需满足 4.5:1。
- **全部使用 `rem`**，`html { font-size: 16px }` 且不覆盖系统字号；尊重用户 Android 的"字体大小"设置，放大到 130% 不截断（验收项 A10）。
- 禁止 `text-transform: uppercase` 处理中文；仅英文 `caption` 可用 `+0.08em` 字距。

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#0B0E14` | 页面底 |
| `--surface` | `#121826` | 卡片 |
| `--surface-2` | `#18202F` | 抬升卡 / 内嵌区 |
| `--surface-3` | `#202A3B` | 悬停/按下 |
| `--border` | `#1F2634` | 分隔线、卡片描边 |
| `--border-strong` | `#2C3648` | 强调描边 |
| `--text` | `#E8ECF4` | 主文本（对比度 ≈15.5:1） |
| `--text-2` | `#9AA6BC` | 次文本（≈7.4:1） |
| `--text-3` | `#7C879B` | 弱文本（≈5.1:1，仅辅助信息） |
| `--accent` | `#E9B44C` | 琥珀：神圣座位 / 链 / 点亮（≈9.9:1） |
| `--accent-dim` | `#4A3C1E` | 强调色的低透明底 |
| `--success` | `#5FD08A` | 成功 / 熟练度满 / 组存活（≈9.9:1） |

> 琥珀 `--accent` 是唯一的主强调色。它对应"神圣座位"——暖光、灯火、值得坐下的位置。绿/红只承担状态语义，绝不用于装饰。

### 3.2 亮色

| Token | 值 |
|---|---|
| `--bg` | `#FBFAF7`（暖白纸感，非纯白） |
| `--surface` | `#FFFFFF` |
| `--surface-2` | `#F4F2ED` |
| `--surface-3` | `#EBE8E1` |
| `--border` | `#E5E1D8` |
| `--border-strong` | `#D2CCBF` |
| `--text` | `#14181F` |
| `--text-2` | `#4E5A6B` |
| `--text-3` | `#6E7887` |
| `--accent` | `#9A6B12`（暗色琥珀的压暗版，满足 4.7:1） |
| `--success` | `#1E7F4E` |
| `--danger` | `#C4353F` |

**策略**：默认跟随系统 `prefers-color-scheme`；首次进入可让用户选"常暗 / 跟随系统"，产品内**不提供开关式反色**（少一个决策）。

### 3.3 语义色纪律
- 崩塌、永久豁免用 `--danger`，但**不用红色背景块**——用红色描边 + 红色文字 + 图标。红色大面积使用会让产品变成"惩罚器"，直接违背原文反说教调性。
- 熟练度进度环用 `--accent → --success` 的插值，随熟练度提升。
- 所有强调色都必须满足 WCAG AA 4.5:1（正文级）或 3:1（图形/描边级）。

## 4. 间距 · 圆角 · 层级

### 4.1 间距（8pt 栅格，允许 4pt 半档）
`4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 56`

页面左右安全边距 **20px**；卡片内边距 **16px**（紧凑卡 12px）；卡片间距 **12px**。

### 4.2 圆角
| Token | 值 | 用途 |
|---|---|---|
| `--r-sm` | 8px | 标签、chip |
| `--r-md` | 14px | 按钮、输入 |
| `--r-lg` | 20px | 卡片 |
| `--r-xl` | 28px | 底部弹层 sheet |
| `--r-full` | 999px | 圆形按钮、头像、进度点 |

> 圆角偏大（14–20）而非 8：Android 上大圆角 + 深色底 + 极细描边，呈现"精密仪器"感，与等宽数字和工程化语气一致。

### 4.3 层级表达（暗色下不用投影）
暗色界面里阴影几乎不可见，改用**描边 + 极轻内发光**：
- `--shadow-pop`: `0 8px 28px rgba(0,0,0,.55)`（仅底部 sheet 与弹窗）
- 卡片抬升：`border: 1px solid var(--border)` + `background: linear-gradient(180deg, var(--surface), var(--surface-2))` 极轻渐变

### 4.4 触控规范（Android 优先，单手）
- 所有可点区域 **≥ 48×48dp**（Material 规范），主按钮高度 **52dp**。
- 主操作区落在**屏幕下 1/3 拇指热区**；破坏性/次要操作放上方。
- 底部导航高度 **64dp + env(safe-area-inset-bottom)**。
- 底部导航 **4 项 + 中央 1 个大按钮（FAB）**，共 5 槽：
  `今日 · 国策树 ·  [链]  · 判例 · 诊断`
  链是唯一的原子高频操作，视觉权重最高。
- **零悬停依赖**，所有 hover 态在触屏上降级为按下态。

### 4.5 图标
- 线性图标，1.75px 描边，20px（列表）/ 24px（导航）。
- 建议 Lucide（MIT，SVG 精简），仅取用约 30 个图标，不引整套。
- 状态不靠图标单独承载，必须配文字或颜色（色觉可达性）。

## 5. 动效规范

> 用户的原话："交互要有动效，界面设计要合理科学"。动效在这里不是装饰，是**因果关系的可视化**——每个动效必须回答"什么变成了什么"。

### 5.1 动效三原则

1. **因果可见**：状态变化必须有连续的运动轨迹（FLIP / 路径生长），不能凭空闪现。
2. **即时反馈**：点击反馈 ≤ 100ms；状态切换 200–280ms；结构性变化 320–420ms。**慢即是错**。
3. **动效是解释，不是奖励**：不给连续打卡放烟花。庆祝只保留一处（见 5.3 第 9 条）。

### 5.2 缓动与时长

| Token | 曲线 | 时长 | 用途 |
|---|---|---|---|
| `--ease-out` | `cubic-bezier(.2,0,0,1)` | 200ms | 进入、展开 |
| `--ease-spring` | `cubic-bezier(.34,1.56,.64,1)` | 320ms | 强调、点亮、按下回弹 |
| `--ease-in` | `cubic-bezier(.4,0,1,1)` | 150ms | 退出、折叠 |
| `--ease-soft` | `cubic-bezier(.33,1,.68,1)` | 280ms | 页面转场 |

**连锁 stagger**：子树类动效按深度错开 **60–70ms**，形成"逐级传导"的物理感（对应原文"连锁反应"）。

### 5.3 关键动效清单

| # | 场景 | 动效描述 |
|---|---|---|
| 1 | **落座** | 锚点卡片描边由虚线呼吸态（2s 循环，opacity .35→.8）→ 变实线；一圈琥珀光环 `scale .8→1.5, opacity 1→0`（480ms ease-out）；同时页面顶部链卡展开 |
| 2 | **链节点 +1** | 链号 `#N` 翻牌（旧号上移 24px 淡出、新号下方淡入，220ms）；链节之间的连线用 SVG `stroke-dashoffset` 生长 320ms |
| 3 | **判例弹层** | 底部 sheet 从 `translateY(100%)` spring 上滑（320ms），背板 `rgba(0,0,0,.6)` 淡入 + 内容 `scale .98→1` |
| 4 | **"永久允许"选择** | 该选项卡红色描边脉冲 **一次**（`scale 1→1.015→1`，260ms），下方后果文案逐行淡入（每行 stagger 40ms）。**只警示一次，不闪烁、不拦阻** |
| 5 | **国策树点亮** | 节点 `scale .6→1` spring + 琥珀辉光扩散 340ms；到父节点的连线同步生长 340ms；同批子节点按序 stagger 60ms |
| 6 | **崩塌（熄节点）** | 节点降饱和 + `translateY(6px)` 淡出 240ms；其子树**按深度 stagger 70ms 连锁熄灭**；同时 `navigator.vibrate(30)` 一次轻触感（Android）；屏幕不闪红 |
| 7 | **熟练度环** | `stroke-dashoffset` 600ms ease-out 过渡；满 100% 时一次性光环 + `vibrate(12)` |
| 8 | **预约倒计时** | 环形进度实时绘制；最后 60 秒数字每秒脉动 `scale 1→1.06`；到点后全屏一次柔和琥珀闪（150ms），不持续 |
| 9 | **阶段结算（今日完成）** | 全屏仅此一处庆祝：锚点卡光晕扩散 + 熟练度环填充 600ms + 一行文字淡入。**禁止**彩带、撒花、连击音 |
| 10 | **页面转场** | `opacity 0→1` + `translateY 12px→0`，280ms ease-soft；底部导航图标切换弹性缩放 `scale .88→1` |
| 11 | **树结构重排** | FLIP：旧位置 → 新位置的位移补间 320ms，节点尺寸变化同时补间 |
| 12 | **折叠/展开国策组** | 高度动画 240ms（内容用 `grid-template-rows: 0fr→1fr` 避免 reflow 抖动） |

### 5.4 Android 性能硬规则

| 规则 | 原因 |
|---|---|
| **只动 `transform` / `opacity`** | 这两个属性走 GPU 合成，不触发 layout/paint |
| **禁用 `width/height/top/left/left` 动画** | 会触发布局，中低端机必掉帧 |
| **禁用大面积 `backdrop-filter`** | Android 上毛玻璃极贵；改用半透明纯色叠加 |
| **阴影动画用 opacity 叠加层**，不动画 `box-shadow` | `box-shadow` 动画触发重绘 |
| **长列表用 `content-visibility: auto` + `contain-intrinsic-size`** | 树节点多时保住滚动帧率 |
| **`will-change` 仅在动效期间动态加** | 常驻会占显存 |
| **尊重 `prefers-reduced-motion`** | 降级为 80ms 纯淡入淡出，取消位移/缩放/连锁/脉动（验收项 A9） |
| 动效预算分级 | 低端机（`deviceMemory ≤ 4` 或 `hardwareConcurrency ≤ 4`）自动关闭光环、脉动与辉光，仅保留位移与透明度 |

### 5.5 触觉反馈（Android）
`navigator.vibrate` 仅用于三处：**崩塌、熟练度满、结算完成**。不用于点击、不用于倒计时滴答。

## 6. 组件基线

| 组件 | 要点 |
|---|---|
| `Card` | 20px 圆角，1px 描边，内边距 16px，卡间距 12px |
| `PrimaryButton` | 高 52dp，`--accent` 实底 + 深色文字（琥珀底必须配深字，保证对比） |
| `GhostButton` | 透明底 + 1px 描边，用于次要/破坏性 |
| `BottomSheet` | 底部弹出，含拖拽把手，下缘圆角 28px，可下滑关闭；Android 返回键优先关闭它 |
| `ChainNode` | 等宽数字 `#N` + 锚点图标 + 状态点；点亮态琥珀辉光 |
| `PolicyNode` | 树节点：4px 状态色点 + 名称 + 等级徽标 + 熟练度细环 |
| `Sheet`（判例二选一） | 两个大按钮，**后果写在按钮内部**（不是弹窗警告） |
| `Ring` | 熟练度/倒计时进度环，SVG `stroke-dasharray` |
| `Chip` | 标签 / 等级 / 组容错名额 |
| `Toast` | 轻量反馈（仅暗色浮层，2.2s 自动消失），**不做成功/失败色语义** |

### 6.1 判例二选一（最关键的组件，原样呈现）

```
┌─────────────────────────────────────┐
│  这次中断：中途看了微信              │
│                                     │
│  ○ 判定违规                          │
│    本链清零，从 #3 重新开始          │
│                                     │
│  ○ 永久允许「中途看微信」             │
│    此后所有链中该行为均合法，          │
│    「最好的状态」判定标准永久放宽      │
│                         [ 确认 ]     │
└─────────────────────────────────────┘
```

设计要点：
- 两个选项**地位平等、无预选**，不诱导选择"更安全"的那个。
- "永久允许"的代价写在**按钮内部正文**，不是确认弹窗。原文的逻辑是"让当下这一刻的决策显式承担长远代价"，藏在二级弹窗里就失效了。
- 选择"永久允许"时，该选项红色描边脉冲一次 + 后果文案逐行淡入（动效 4）。
- **不存在"永久禁止"选项**——永久禁止会制造过强预期导致崩溃。禁止是默认态，豁免才是需要显式承担的动作。
