## 1. 全局导航

底部 4 项 + 中央 FAB，共 5 槽（Android 单手拇指热区）：

```
┌──────────────────────────────────────────┐
│  今日     国策树    ( 链 )   判例    诊断  │
└──────────────────────────────────────────┘
```

- **今日**：结算页。每天的主要动作在这里发生。
- **国策树**：全景。视图与结构。
- **链 FAB**：唯一的高频原子操作。点击直接进入"预约 / 落座"的最短路径（1 次点击）。
- **判例**：永久豁免清单。产品的"账本"。
- **诊断**：尺度诊断、国策设计器、崩塌复盘。

**Android 返回键优先级**（从高到低）：
1. 关闭 BottomSheet / Dialog
2. 关闭全屏链视图 → 回今日页
3. 退出"国策设计器"的提示词输入态
4. 回上一页
5. 退出 PWA（最后一步，交还系统）

**要点**
- 链卡在**未落座**时，主体变为一块高 140dp 的琥珀描边区，中央是"落座"和"预约 15 分钟后"两个大按钮（预约为主按钮，因为预约的启动阻力更低——直接对应原文的线性时延原理）。
- 今日结算卡**永远只有一个可点的"我今天做到了"**。这是 RSIP 的引擎动作，不能变成清单。
- 「连续点亮 12 天」刻意**不叫"连续打卡"**，且用"熟练度"替代"坚持"，避免打卡式压力。
- 一句话复盘可跳过，不做强制。

### 2.2 链（全屏，从 FAB 进入）

```
┌────────────────────────────────────────────┐
│  ✕                                    #3   │
│                                             │
│           ╭───────────╮                     │
│           │  ◜  环    │  37:12              │
│           │  进度 + 数字 │                   │
│           ╰───────────╯                     │
│                                             │
│      ◆ 锚点：书房那张桌子                     │
│      判定标准：以最好的状态专注               │
│                                             │
│  ── 链节 ──────────────────────────────     │
│  #1 ✓  已完成        10:02–11:01            │
│  #2 ✓  已完成        11:20–12:21            │
│  #3 ●  进行中        13:05–                │
│                                             │
│  ── 本链判例 ────────────────────────────   │
│  本链尚未判定过任何中断                       │
│                                             │
├────────────────────────────────────────────┤
│  [ 判定一次中断 ]        [ 结束本链 ]        │
└────────────────────────────────────────────┘
```

- 环同时承载**时间**与**进度**两种信息容易糊，拆开：外环＝已过时间比例，内数字＝倒计时。
- 「本链判例」区始终可见——让用户看到"这条链上我放过什么"，这是判例机制的可见性来源。
- 结束本链 → 若有中断未判定，先弹判定；否则直接结算，熟练度 +1。

```
┌────────────────────────────────────────────┐
│  国策树              树形 │ 列表    [+]     │
├────────────────────────────────────────────┤
│  点亮 12 · 手牌 7 · 组 3 · 熟练度 34%        │
│                                             │
│         ●#1 吃完饭立即洗碗  [68%]           │
│         │                                    │
│         ├── ●#4 回家进门先洗澡  [45%]        │
│         │    │                               │
│         │    └── ○#9 睡前手机放客厅 (手牌)     │
│         │                                    │
│         ├── ●#7 23:00 只能站着玩手机 [22%]   │
│         │                                    │
│         └── ●#12 起床30分钟不碰手机 [55%]     │
│                                             │
│  ┌─ 折叠的组 ──────────────────────────┐    │
│  │ ▸ 作息组  4/5 存活 · 容错名额 1        │    │
│  │ ▸ 精力组  3/3 存活                    │    │
│  └────────────────────────────────────────┘    │
│                                             │
├────────────────────────────────────────────┤
│  今日     国策树    ( 链 )   判例    诊断  │
└────────────────────────────────────────────┘
```

**交互**
- **点节点** → 底部面板：名称 / 触发条件 / 判定标准 / 阻力·杠杆·维护成本估算 / 熟练度 / 子节点 / 操作（设为今日目标、升级、拆分、放回手牌、归档）。
- **长按节点** → 拖拽重挂父子关系（带吸附线）。
- **[+] 顶部按钮** → 添加国策：手动填 或 打开设计器。
- **点组** → 展开组成员 + 容错名额状态；组内熄灭数达上限 → 组熄灭 → 子孙熄灭。
- 树视图超过 60 节点自动折叠深层并提示"按组查看"。

**视图切换（树形/列表）**很重要：Android 小屏上树不一定可读，列表视图（按组/按状态排序）对每日结算场景更高效。

### 2.4 判例（Ledger）

```
┌────────────────────────────────────────────┐
│  判例                                        │
├────────────────────────────────────────────┤
│  ▸ 永久豁免 (3)                             │
│  ┌──────────────────────────────────────┐  │
│  │ 中途看微信            授予于 10月12日  │  │
│  │ 已放行 23 次                          │  │
│  │ 影响：#1 链判定标准、#7 判定标准       │  │
│  └──────────────────────────────────────┘  │
│  ┌──────────────────────────────────────┐  │
│  │ 接工作电话            授予于 10月03日  │  │
│  │ 已放行 7 次                           │  │
│  │ 影响：#1 链判定标准                   │  │
│  └──────────────────────────────────────┘  │
│                                             │
│  ▸ 永久禁止                                  │
│  开车看手机 · 独自饮酒 · 通宵 · 跳过必要就医  │
│                                             │
│  ▸ 今日放行                                  │
│  14:20 中途看微信（#2 链）                  │
│                                             │
├────────────────────────────────────────────┤
│  今日     国策树    ( 链 )   判例    诊断  │
└────────────────────────────────────────────┘
```

**要点**
- 每条永久豁免必须显示**影响面**（削弱了哪些判定标准）与**放行次数**。这是让"永久"这一概念有实感的关键。
- 永久禁止清单**只读**，不可豁免（安全加固，已被确认接受）。
- ⚠️ 豁免**不可单条撤销**——这是"永久"的定义。但提供全局操作"清空全部豁免并重建"，让用户可以主动重置（代价：所有受影响链的判定标准收紧，可能触发崩塌）。这是有意的摩擦设计。
- 「今日放行」记录本日的每次永久豁免授予动作——用户点下去的那一瞬间它就产生，不可事后撤销。

### 2.5 诊断（Diagnose）

```
┌────────────────────────────────────────────┐
│  诊断                                        │
├────────────────────────────────────────────┤
│  ▸ 稳态诊断                                  │
│  [ 描述你昨天是怎么过的 ]                    │
│  → 输出：日级稳态 / 周级稳态 / 有效干预节点    │
│                                             │
│  ▸ 国策设计器                                │
│  遇到的问题：_______________                  │
│  [ 生成本地候选 ]  [ 与 AI 共演 ]             │
│                                             │
│  ▸ 崩溃复盘                                  │
│  最近 7 天熄灭 2 个国策 · 查看复盘             │
│                                             │
│  ▸ 方法论出处                                 │
│  《如何提高自制力：CTDP 与 RSIP》· 作者署名  │
└────────────────────────────────────────────┘
```

**"与 AI 共演"流程**（零后端、零密钥）：

```
① 用户填写问题
② 点「生成提示词」→ 页面显示一段结构化提示词（含方法论要点与输出 JSON Schema）
③ 「复制提示词」→ 用户粘到任意 AI
④ AI 返回 JSON → 粘贴回产品的文本框
⑤ 产品解析 + 校验 → 展示为候选国策卡 → 「点亮」
```

原文作者在后记里亲自建议读者"把本文复制给 ChatGPT 辅助理解"——这个模式是原文原生建议的延续，不是妥协。

**本地候选引擎**（不依赖 AI 的兜底）：
结构化定式库 + 三类分解算法（原文 §19）：
- **堵入口**（回溯上游节点）
- **降切换难度**（A→A'→A'' 阶梯）
- **借环境力量**（借因果链 / 行为惯性 / 物理姿势 / 生理本能 / 数学结构）
每类产出候选卡，标注 `阻力 / 杠杆 / 维护成本 / 类型(被动|半被动|主动)`，被动/半被动优先排序（对应攻略三）。

## 3. 关键流程

### F1 · 预约 → 落座 → 结算
```
[FAB] → 选"预约 15 分钟后" → 选择锚点 + 任务描述
      → 系统闹钟/ICS 提醒（可选）+ 页内倒计时
      → 到点 → 全屏轻闪 + 「落座」按钮
      → 落座 → 链 #1 开始（熟练度不参与，链号从 #1）
      → … 完成 → 结束本链 → 熟练度 +1
```
**摩擦设计**：预约按钮是 FAB 的默认落点（"预约"阻力低于"立即"），落座按钮在预约到点时自动置为唯一主操作。

### F2 · 中断判定（最关键）
```
链进行中 → [判定一次中断] → 选择行为（常用 chip + 自定义）
        → 弹出判例二选一（判例组件，见设计系统 §6.1）
        ├─ 判定违规 → 本链清零（#N → 回到 #1）→ 熟练度保留
        └─ 永久允许 → 写入全局判例表 → 本链继续，本链判例区显示
```
「判定一次中断」的入口在链卡上常驻，但**不自动弹出**——不主动打断用户的沉浸。

### F3 · 每日点亮一个国策
```
今日结算卡 [我今天做到了] → 选国策（手牌抽屉 / 新建）
   → 确认 → 写入事件 → 树更新（父节点默认=昨日点亮的国策）
   → 熟练度进度条 +1
```
默认父节点规则（对应原文"如果我发现 H 定式和已有的 F 定式高度相关，我可以将 H 作为 F 的子节点加入"）：优先挂到**昨日点亮的国策**下（形成连续路径），用户可改挂。

### F4 · 崩塌与重建
```
国策熄灭 → 子树连锁熄灭（动效 6）
        → 崩溃复盘（编译器风格）
        → 五类归因：维护成本高 / 疲劳 / 忘记 / 做不到 / 与已有定式冲突
        → 一键修正：降级重试 / 改判定标准 / 加前置国策 / 放回手牌 / 归档
        → 熟练度全部保留
```
**编译器风格示例**：
```
✕ 国策 #7「23:30 必须睡觉」未能点亮
  ├ 依赖 #3「23:00 后只能站着玩手机」— 已点亮
  ├ 冲突：与 #5「22:45 躺平」阈值不一致
  ├ 归因：近 3 次崩溃均发生在「DDL 前期 · 睡眠不足」
  └ 建议 ① 降级为 L1「23:30 躺下，不要求睡着」
          ② 前置国策 #11「睡前手机放客厅充电」
          ③ 合并 #5 与 #7 为「作息储备」组
```
**关键**：全文用系统日志语气，无"你失败了""坚持不住"这类词。红色仅用于描边与文字，不用红色块。

### F5 · 从稳态到国策（获客主线）
```
诊断 → 输入昨日时间线 → 输出稳态剧本 + 有效干预节点
     → 为该节点生成 3 个候选国策（本地引擎 / AI 共演）
     → 点亮第一个（难度最低的那个）
     → 次日结算 → 继续
```
第一天的目标不是"立住很多国策"，而是**只点亮一个**。产品应在这一步明确告诉用户："今天只需要一个。"

## 4. Android 适配

### 4.1 通知策略（无后端下的双通道）

| 提醒 | 通道 A | 通道 B（兜底） |
|---|---|---|
| 预约倒计时到点 | 页内实时倒计时 + 全屏轻闪 | **导出系统日历/闹钟 (.ics)**，VALARM 提前 0 分钟触发，Android 原生闹钟最可靠 |
| 链该结束了 | 页内提示 | — |
| 崩塌发生 | 即时页内 | — |
| 今日待结算 | 次日首次打开时顶部提示 | 系统通知（可选授权） |

> `.ics` 是静态托管的关键补丁：它把提醒责任完全交给 Android 系统闹钟，**不需要任何后端**，且能穿透"App 被系统杀死"和"浏览器被回收"两种情况。产品需引导用户首次使用时开启。

### 4.2 其他 Android 细节
- **PWA 安装引导**：捕获 `beforeinstallprompt`，在首次启动链后提示"添加到主屏幕"（此时用户已经尝到甜头，转化最高）。
- **保持屏幕常亮**：链进行中使用 Wake Lock API（倒计时/阅读场景需要），结束自动释放。
- **触感**：`navigator.vibrate` 三处（崩塌 / 熟练度满 / 结算完成）。
- **系统返回键**：按 §1 优先级处理，`popstate` 拦截。
- **IME**：所有文本输入 `enterkeyhint`、`autocapitalize="off"`、`autocomplete="off"`；中文输入法组合期不触发校验。
- **系统字号**：全 `rem`，支持到 130% 放大不截断（验收 A10）。
- **安全区**：`env(safe-area-inset-bottom)` 用于底部导航；`viewport-fit=cover`。
- **深色模式**：跟随系统（验收默认态即为暗色优先的精致暗色 + 系统浅色适配）。
- **分享**：`navigator.share`（Android Chrome 原生支持），分享内容**只含国策与定式**，不含失败率与中断历史。
- **不要依赖 iOS 专属 API**（不引 PWA 必需之外的 Safari 特性），保持代码可移植，便于未来用 Capacitor 套壳。

## 5. 空状态与首次使用

首次进入**不做**目标设定表单（会立刻制造主动决策负荷）。流程：

```
① 选难度档（用 3 个描述句代替问卷）
② 选一个实体锚（可拍照 / 从预置模板选 / 手写描述）
③ 选今天要做的一件小事 → 直接进入第一次链
④ 第一次链完成后 → 才介绍国策树与判例
```
第 ④ 步之前**不出现**国策树、不出现任何"国策库"浏览界面。原则：先给一个成功的微体验，再给复杂度。
